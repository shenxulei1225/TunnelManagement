# 通用分类系统菜单配置

## 概述

通用分类系统通过统一的API和数据结构，支持多种业务类型的分类管理。每个业务类型都可以通过菜单管理自动创建对应的页面。

## 最终推荐方案

### 数据库表结构

```sql
-- 分类表
CREATE TABLE system_category (
  id BIGINT PRIMARY KEY,
  parent_id BIGINT NOT NULL,
  code VARCHAR(32) NOT NULL,
  category_type VARCHAR(50) NOT NULL, -- 分类类型
  name VARCHAR(64) NOT NULL,
  description VARCHAR(255),
  icon VARCHAR(100),
  color VARCHAR(20),
  status TINYINT NOT NULL DEFAULT 1,
  -- 其他字段...
);

-- 关联表
CREATE TABLE system_item_category_rel (
  id BIGINT PRIMARY KEY,
  item_id BIGINT NOT NULL,
  item_type VARCHAR(50) NOT NULL, -- 业务类型
  category_id BIGINT NOT NULL,
  category_type VARCHAR(50) NOT NULL, -- 分类类型
  -- 其他字段...
);
```

### 支持的业务类型和分类类型

| 业务类型 (item_type) | 分类类型 (category_type) | 说明 |
|---------------------|------------------------|------|
| device | area, facility, status | 设备管理 |
| product | brand, category, status | 产品管理 |
| user | department, role, status | 用户管理 |
| field_def | field, type, status | 字段管理 |

## API接口配置

### 通用分类API

```typescript
// 分类树接口
GET /system/category/tree?categoryType={categoryType}

// 分类列表接口
GET /system/category/list?categoryType={categoryType}&pageNo={pageNo}&pageSize={pageSize}

// 分类详情接口
GET /system/category/{id}

// 创建分类接口
POST /system/category

// 更新分类接口
PUT /system/category/{id}

// 删除分类接口
DELETE /system/category/{id}

// 获取分类下的数据项
GET /system/category/items?itemType={itemType}&categoryId={categoryId}

// 添加数据项到分类
POST /system/category/item

// 从分类移除数据项
DELETE /system/category/item

// 按业务类型获取分类
GET /system/category/by-item-type?itemType={itemType}

// 按分类类型获取数据项
GET /system/category/items/by-category-type?categoryType={categoryType}&itemType={itemType}
```

## 优势

1. **统一架构**: 所有业务类型使用相同的组件和API
2. **减少重复**: 不需要为每个业务创建独立的DO、Controller、Service
3. **易于扩展**: 新增业务类型只需配置菜单和分类数据
4. **维护简单**: 统一的代码结构，便于维护和升级
5. **性能优化**: 统一的缓存策略和查询优化
6. **动态业务友好**: 支持自动生成代码和灵活查询

## 注意事项

1. **业务类型标识**: 确保每个业务类型有唯一的标识符
2. **权限控制**: 为不同业务类型配置相应的权限
3. **数据隔离**: 通过tenant_id实现多租户数据隔离
4. **分类管理**: 定期清理无用的分类数据
5. **性能监控**: 监控分类查询和数据关联的性能
