# 通用分类系统实施指南

## 概述

本指南将帮助您安全地实施通用分类系统，避免重复字段和数据冲突。

## 实施步骤

### 1. 检查现有数据库结构

首先运行检查脚本，了解当前数据库结构：

```bash
mysql -u username -p database_name < sql/mysql/check_database_structure.sql
```

这将显示：
- 现有表结构
- 已存在的字段
- 现有索引
- 现有触发器
- 数据量统计

### 2. 执行安全迁移脚本

运行安全迁移脚本，自动检查并添加必要字段：

```bash
mysql -u username -p database_name < sql/mysql/20250116_migrate_category_system.sql
```

此脚本会：
- ✅ 检查并添加 `category_type` 字段（如果不存在）
- ✅ 检查并添加 `description`、`icon`、`color` 字段（如果不存在）
- ✅ 检查并添加必要索引（如果不存在）
- ✅ 创建 `system_item_category_rel` 表（如果不存在）
- ✅ 创建自动维护触发器（如果不存在）
- ✅ 创建分类树视图
- ✅ 初始化基础分类数据

### 3. 验证迁移结果

运行验证脚本确认迁移成功：

```sql
-- 检查字段是否添加成功
SELECT COLUMN_NAME, DATA_TYPE, IS_NULLABLE, COLUMN_DEFAULT, COLUMN_COMMENT
FROM INFORMATION_SCHEMA.COLUMNS 
WHERE TABLE_SCHEMA = DATABASE() 
  AND TABLE_NAME = 'system_category'
  AND COLUMN_NAME IN ('category_type', 'description', 'icon', 'color')
ORDER BY ORDINAL_POSITION;

-- 检查关联表是否创建成功
SELECT COUNT(*) as table_exists
FROM INFORMATION_SCHEMA.TABLES 
WHERE TABLE_SCHEMA = DATABASE() 
  AND TABLE_NAME = 'system_item_category_rel';

-- 检查触发器是否创建成功
SELECT TRIGGER_NAME, EVENT_MANIPULATION, EVENT_OBJECT_TABLE
FROM INFORMATION_SCHEMA.TRIGGERS 
WHERE TRIGGER_SCHEMA = DATABASE() 
  AND EVENT_OBJECT_TABLE = 'system_item_category_rel';

-- 检查视图是否创建成功
SELECT COUNT(*) as view_exists
FROM INFORMATION_SCHEMA.VIEWS 
WHERE TABLE_SCHEMA = DATABASE() 
  AND TABLE_NAME = 'v_system_category_tree';
```

## 支持的业务类型和分类类型

| 业务类型 (item_type) | 分类类型 (category_type) | 说明 |
|---------------------|------------------------|------|
| device | area, facility, status | 设备管理 |
| product | brand, category, status | 产品管理 |
| user | department, role, status | 用户管理 |
| field_def | field, type, status | 字段管理 |

## API接口

### 分类管理接口

```typescript
// 获取分类树
GET /system/category/tree?categoryType={categoryType}

// 获取分类列表
GET /system/category/list?categoryType={categoryType}&pageNo={pageNo}&pageSize={pageSize}

// 获取分类详情
GET /system/category/{id}

// 创建分类
POST /system/category

// 更新分类
PUT /system/category/{id}

// 删除分类
DELETE /system/category/{id}
```

### 数据关联接口

```typescript
// 获取分类下的数据项
GET /system/category/items?itemType={itemType}&categoryId={categoryId}

// 添加数据项到分类
POST /system/category/item

// 从分类移除数据项
DELETE /system/category/item

// 按业务类型获取分类
GET /system/category/by-item-type?itemType={itemType}

// 按分类类型获取数据项
GET /system/category/items/by-category-type?categoryType={categoryType}&itemType={itemType}
```

## 数据库表结构

### system_category 表

```sql
CREATE TABLE system_category (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  parent_id BIGINT NOT NULL DEFAULT 0,
  code VARCHAR(32) NOT NULL,
  category_type VARCHAR(50) NOT NULL DEFAULT 'default',
  name VARCHAR(64) NOT NULL,
  description VARCHAR(255),
  icon VARCHAR(100),
  color VARCHAR(20),
  status TINYINT NOT NULL DEFAULT 1,
  tree_path VARCHAR(256) NOT NULL,
  level TINYINT NOT NULL DEFAULT 1,
  sort INT NOT NULL DEFAULT 0,
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted TINYINT NOT NULL DEFAULT 0,
  tenant_id BIGINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_category_type (category_type),
  KEY idx_status (status),
  KEY idx_parent_id (parent_id)
);
```

### system_item_category_rel 表

```sql
CREATE TABLE system_item_category_rel (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  item_id BIGINT NOT NULL,
  item_type VARCHAR(50) NOT NULL,
  category_id BIGINT NOT NULL,
  category_type VARCHAR(50) NOT NULL,
  sort_order INT NOT NULL DEFAULT 0,
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted TINYINT NOT NULL DEFAULT 0,
  tenant_id BIGINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_item_category (item_id, item_type, category_id, deleted),
  KEY idx_category_id (category_id),
  KEY idx_item_type (item_type),
  KEY idx_category_type (category_type),
  KEY idx_item_category_type (item_type, category_type),
  KEY idx_category_item_type (category_type, item_type)
);
```

## 优势特点

1. **安全迁移**: 自动检查现有字段，避免重复添加
2. **动态业务友好**: 支持自动生成代码和灵活查询
3. **性能优化**: 包含 `category_type` 字段，避免JOIN操作
4. **易于扩展**: 新增业务类型只需配置菜单和分类数据
5. **统一架构**: 所有业务类型使用相同的组件和API

## 注意事项

1. **备份数据**: 执行迁移前请备份数据库
2. **测试环境**: 建议先在测试环境验证
3. **权限检查**: 确保数据库用户有足够权限
4. **数据验证**: 迁移后验证数据完整性
5. **性能监控**: 监控查询性能，必要时调整索引

## 故障排除

### 常见问题

1. **字段已存在错误**
   - 脚本会自动检查并跳过已存在的字段
   - 这是正常行为，无需担心

2. **权限不足错误**
   - 确保数据库用户有 ALTER、CREATE、INSERT 权限
   - 联系数据库管理员获取必要权限

3. **触发器创建失败**
   - 检查 MySQL 版本是否支持触发器
   - 确保有 CREATE TRIGGER 权限

4. **数据插入失败**
   - 检查外键约束
   - 确保父记录存在

### 回滚方案

如果需要回滚，可以执行以下操作：

```sql
-- 删除触发器
DROP TRIGGER IF EXISTS tr_item_category_rel_insert;
DROP TRIGGER IF EXISTS tr_item_category_rel_update;

-- 删除关联表
DROP TABLE IF EXISTS system_item_category_rel;

-- 删除视图
DROP VIEW IF EXISTS v_system_category_tree;

-- 删除添加的字段（谨慎操作）
-- ALTER TABLE system_category DROP COLUMN category_type;
-- ALTER TABLE system_category DROP COLUMN description;
-- ALTER TABLE system_category DROP COLUMN icon;
-- ALTER TABLE system_category DROP COLUMN color;
```
