# 分类系统性能分析

## 写入少查询多的场景分析

### 性能对比数据

| 方案 | 表大小 | 索引数量 | 查询复杂度 | 写入性能 | 查询性能 | 推荐度 |
|------|--------|----------|------------|----------|----------|--------|
| 最简化方案 | 小 | 2个 | 简单 | 高 | **最高** | ⭐⭐⭐⭐⭐ |
| 保留item_type | 中 | 3个 | 中等 | 中 | 高 | ⭐⭐⭐⭐ |
| 完整方案 | 大 | 4个 | 复杂 | 低 | 中 | ⭐⭐⭐ |

### 详细性能分析

#### 1. 最简化方案（推荐）

**表结构：**
```sql
CREATE TABLE system_item_category_rel (
  id BIGINT PRIMARY KEY,
  item_id BIGINT NOT NULL,
  category_id BIGINT NOT NULL,
  UNIQUE KEY uk_item_category (item_id, category_id),
  KEY idx_category_id (category_id),
  KEY idx_item_id (item_id)
);
```

**性能特点：**
- ✅ **查询性能最佳**：单字段索引，查询速度快
- ✅ **存储空间最小**：字段最少，节省存储
- ✅ **索引效率高**：索引数量少，维护成本低
- ✅ **写入性能好**：字段少，写入速度快
- ❌ **业务逻辑复杂**：需要通过其他方式区分业务类型

**适用场景：**
- 查询频率 > 写入频率
- 对查询性能要求高
- 存储空间有限
- 业务逻辑相对简单

#### 2. 保留item_type方案

**表结构：**
```sql
CREATE TABLE system_item_category_rel (
  id BIGINT PRIMARY KEY,
  item_id BIGINT NOT NULL,
  item_type VARCHAR(50) NOT NULL,
  category_id BIGINT NOT NULL,
  UNIQUE KEY uk_item_category (item_id, item_type, category_id),
  KEY idx_category_type (category_id, item_type),
  KEY idx_item_type (item_id, item_type)
);
```

**性能特点：**
- ✅ **查询性能好**：复合索引，查询速度较快
- ✅ **业务逻辑清晰**：通过item_type区分业务类型
- ❌ **存储空间较大**：多一个字段
- ❌ **索引复杂度高**：复合索引维护成本高
- ❌ **写入性能中等**：字段较多

**适用场景：**
- 需要区分不同业务类型
- 查询和写入频率相当
- 对业务逻辑清晰度要求高

#### 3. 完整方案（不推荐）

**表结构：**
```sql
CREATE TABLE system_item_category_rel (
  id BIGINT PRIMARY KEY,
  item_id BIGINT NOT NULL,
  item_type VARCHAR(50) NOT NULL,
  category_id BIGINT NOT NULL,
  relation_type VARCHAR(50) NOT NULL,
  UNIQUE KEY uk_item_category (item_id, item_type, category_id, relation_type),
  KEY idx_category_type (category_id, item_type),
  KEY idx_item_type (item_id, item_type),
  KEY idx_relation_type (relation_type)
);
```

**性能特点：**
- ❌ **查询性能中等**：索引复杂，查询速度一般
- ❌ **存储空间最大**：字段最多
- ❌ **索引维护成本高**：索引数量多
- ❌ **写入性能低**：字段多，写入慢
- ✅ **功能最完整**：支持主次关联关系

## 查询性能测试

## 推荐方案

### 对于写入少查询多的场景

**强烈推荐：最简化方案**

**理由：**
1. **查询性能最佳**：单字段索引，查询速度最快
2. **存储效率最高**：字段最少，节省存储空间
3. **索引维护成本最低**：索引数量少，维护简单
4. **写入性能好**：字段少，写入速度快

**实现方式：**
```sql
-- 最简化的关联表
CREATE TABLE system_item_category_rel (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  item_id BIGINT NOT NULL,
  category_id BIGINT NOT NULL,
  sort_order INT NOT NULL DEFAULT 0,
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted TINYINT NOT NULL DEFAULT 0,
  tenant_id BIGINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_item_category (item_id, category_id, deleted),
  KEY idx_category_id (category_id),
  KEY idx_item_id (item_id)
);
```

**业务类型区分方式：**
1. **通过item_id范围**：不同业务使用不同的ID范围
2. **通过业务逻辑**：在应用层区分不同业务类型
3. **通过分类类型**：通过category_type间接区分业务

**查询示例：**
```sql
-- 查询区域分类下的所有数据
SELECT * FROM system_item_category_rel r
JOIN system_category c ON r.category_id = c.id
WHERE c.category_type = 'area' AND c.id = 2;

-- 通过item_id范围区分业务类型
SELECT * FROM system_item_category_rel 
WHERE category_id = 2 
  AND item_id BETWEEN 10000 AND 19999; -- 设备ID范围
```

## 总结

对于**写入少查询多**的场景，最简化方案是最佳选择：

- ✅ **查询性能最佳**
- ✅ **存储效率最高**
- ✅ **维护成本最低**
- ✅ **扩展性最好**

建议采用最简化方案，通过业务逻辑来区分不同业务类型，而不是在数据库层面增加额外的字段。
