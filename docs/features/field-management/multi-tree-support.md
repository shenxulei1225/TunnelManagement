# ExtendTree多树支持实现

## 🎯 问题背景

**用户问题**: "为什么不能支持并列的几棵树？"

**当前限制**:
1. 强制使用单一虚拟根节点（"全部字段"）
2. 所有数据都被塞到虚拟根节点下
3. 不支持多个并列的独立树

## 🔧 解决方案

### 1. **添加显示模式枚举**

```typescript
// 树形结构显示模式
export enum TreeDisplayMode {
  SINGLE_ROOT = 'single_root',      // 单一虚拟根节点模式（默认）
  MULTIPLE_TREES = 'multiple_trees'  // 并列多树模式
}
```

### 2. **改进数据处理逻辑**

```typescript
const processHierarchyData = (data: any) => {
  if (displayMode === TreeDisplayMode.MULTIPLE_TREES) {
    // 多树模式：支持并列的独立树
    if (Array.isArray(data)) {
      return data  // 直接返回并列的树
    } else if (data.children) {
      return data.children  // children作为并列树
    }
  } else {
    // 单根模式：保持虚拟根节点结构（向后兼容）
    const virtualRoot = {
      id: 0,
      name: '全部字段',
      children: Array.isArray(data) ? data : (data.children || [data])
    }
    return [virtualRoot]
  }
}
```

### 3. **用户界面切换**

添加了显示模式切换按钮：
- 📁 单根模式：传统的虚拟根节点模式
- ⊞ 多树模式：支持并列的独立树

## 📊 两种模式对比

### 单根模式（默认）
```
├── 全部字段 (虚拟根节点)
    ├── 建筑分组
    │   └── 子分组A
    ├── 电力分组
    │   └── 子分组B
    └── 通信分组
        └── 子分组C
```

**特点**:
- ✅ 向后兼容现有逻辑
- ✅ 统一的入口点
- ✅ 易于理解和导航
- ❌ 增加了一层不必要的嵌套

### 多树模式（新增）
```
├── 建筑分组
│   └── 子分组A
├── 电力分组
│   └── 子分组B
└── 通信分组
    └── 子分组C
```

**特点**:
- ✅ 更直观的数据展示
- ✅ 减少嵌套层级
- ✅ 支持真正的并列树结构
- ✅ 更符合实际数据结构
- ⚠️ 需要处理多个根节点的选择逻辑

## 🎯 使用场景

### 单根模式适用于：
- 需要统一管理所有分组
- 希望有明确的"全部"概念
- 向后兼容现有业务逻辑
- 数据结构相对简单

### 多树模式适用于：
- 分组之间相对独立
- 希望减少界面层级
- 数据库中确实有多个根节点
- 需要更直观的数据展示
